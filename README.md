### Bezier Clipped Metaballs

Metaballs are a classic rendering technique known for making blobby spheres. It works by treating points in space as having a charge with a falloff- literally, simulating an electromagnetic field- and then finding the "isosurface" around that point, which is just the region where the value of the field reaches a certain threshold. For a single charge, this is just a fancy way of rendering a sphere, but it gets interesting when you start adding multiple metaballs into the mix. The charged fields overlap additively, which creates the distinctive blobby look of metaballs. While initially used to render electron fields in early visualizations of molecules, it's since found a wide range of niche applications, notably, video games.

When my team and I were building [Soar: Pillars of Tasneem](https://store.steampowered.com/app/1513030/Soar_Pillars_of_Tasneem/), we needed an unsettling, out-of-place effect for corruption, and we settled on metaballs as the basis for that look. _Soar_ is low poly, sharp edges and hard lines, something soft and organic would stick out like a sore thumb. However, performance was a problem- due to our time and budget constraints, I was forced to use raymarched rendering, which is slow. Luckily, modern graphics cards are powerful, and, with a lot of help from some very smart people, I was able to optimize it reasonably well. Reasonably is the key word here, a lot of compromises were made, and I never felt satisfied with that implementation.

During my research, I discovered Nishita Lab's seminal work on metaballs, dating back to the 90s. Miraculously, all of their work is publicly available, and I included the relevant snippet of their 1990 paper in this repository. Their approach is as follows: if we shoot a ray through a charged field, the density of that field is guaranteed to be a degree-6 polynomial. While it's been proven that there is no "hexatic equation" that can allow us to solve for some threshold value algebraically, we can easily generate Bezier points that perfectly represent that curve. As it turns out, you can iteratively approximate the X value of any given Y- allowing you to find where the original polynomial (and thus, the charged field itself) reach a certain threshold value that then forms the metaball isosurface. along a Bezier curve using a process called Bezier clipping, which can get good results in fewer than 4 iterations.

Implementing Bezier clipped metaball rendering is trivial on the CPU, but quite challenging on the GPU, and even moreso within the limits of Unreal Engine. I began work on it during _Soar_'s development, first writing a python script to demonstrate my understanding, and then attempting to port that to shader code. While I made some progress, it was ultimately too time consuming to continue working on, but I kept it in the back of my mind. In picking it up again about a year later, LLM tooling had radically improved, so I decided to give it a try. I experimented with a variety of models, and ultimately settled on Opus 5 for both cost and performance reasons. I went back to my original python script, and used Opus 5 to generate a UI and perform validation on it. With that baseline validated, I had Opus translate it into HLSL, then tested and optimized it, and settled on a roughly 2x performance improvement over raymarching- which I am more than happy with.

To test the python code yourself, download the repository and run the batch file. On non-windows systems, run the python command inside of that batchfile in your terminal of choice, it should work the same. To test the shader, you can download my Fab Asset, or see it running in _Soar_.
